# Coverage-focused note repair: failed substantive gate

A stronger prompt and explicit pre-finish coverage review did not make frozen Qwen3-1.7B reliable enough to rerun the paired answer comparison. This bounded validation used only Maya's first two existing sessions, carried actual model notes forward, and made no Luna calls. The dataset and earlier runs remain unchanged.

The prompt now explains that future conversations see only notes; requires every useful disclosed fact, category/brand/season scope, unknown versus empty preference lists, recipients/status/deadlines, dates/history and temporary base/expiry; and forbids filler and invented facts. On the first valid no_op, the harness returns a coverage-review request with the notes already saved, then lets the model add missing facts or finish. This is a deliberate interaction change, logged in config.json and every trace. There is no content-dependent oracle judgment or automatic note repair. The review stays within12 calls/session and the existing768-token output limit.

Session1 completed6 valid calls out of6. It saved the name, summer-pants linen/cotton preference, unknown hat size, empty accessories-pattern preference, both intent statuses/deadlines and accessories brands. However, intent identifiers/recipients and evidence dates were omitted. The notes also included café chatter and unsupported claims “Occasion: casual” and “Brand and sizing system: no preference”; summer was mislabeled as subtype. The coverage reminder did not correct these defects.

Session2 completed3 valid calls out of4. One response contained two put_note calls and was correctly rejected. Those attempted writes merely repeated the old notes. No accepted write followed: the model finished, reviewed, then finished again with notes unchanged. It missed the temporary cotton preference and exact expiry, the newly disclosed functional/modern outerwear styles and the occupation. Earlier contents were retained, including their errors. This does not demonstrate correct temporal update handling.

All9 accepted calls across10 rounds were processed under the unchanged strict tool-argument validator. The one malformed multi-call response did not mutate notes. Calls used the native Qwen tools-aware chat template, greedy decoding and thinking disabled. Model revision:70d244cc86ccca08cf5af4e1e306ecf908b1ad5e; weights verified before loading; no weight training. Native tool wrapper parsing and dispatcher transport mapping are explicit, with no silent tool renaming.

Protocol validity improved relative to the original120/120 failures, but factual selectivity, completeness and updates still fail. No replacement20-question answer evaluation was run. The original40% baseline/50% nominal-memory results still describe the failed empty-note run and must not be presented as results of this repair. This two-session test does not establish robustness to unavailable tools or broad generalization.
